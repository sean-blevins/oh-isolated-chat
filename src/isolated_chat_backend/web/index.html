Isolated Docker Chat

An isolated conversation runs in its own container: Canvas cannot fork it, and new conversations start from an empty runtime directory. This page is the host side of that gap. Promote merges a conversation's memory into the durable store that new conversations are seeded from, as a line union: it only adds lines the durable store does not already have, and never rewrites the conversation's copy. Fork copies a conversation's full history and state into a new conversation, on the source's own LLM profile or on another one you pick per row. Hand over starts a fresh conversation seeded with the conversation's handover.md and no carried context, linking back so the chain can be followed. Open jumps to the conversation in Canvas and Delete removes it there and drops its local runtime directory; promoted memory is kept.

New conversation

Starts a conversation this app owns: it seeds the plugin into the conversation's runtime directory before creating it, so the container's first run already has it. The plugin carries a handover skill and a hook that logs to .openhands/handover/hook.log, counts runs, and detects a handover request. The conversation launches on the chosen agent profile, with the chosen LLM profile overriding the profile's own — the same path Canvas's own launcher uses, so the credentials are resolved by the Agent Server and never handled here.
